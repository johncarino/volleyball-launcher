## The Bazel rebuild — what happened and why

### What happened
While iterating on the recognizer on the board, a normal-looking build turned into a
**full MediaPipe rebuild** (recompiling all of Abseil/gflags/etc. from scratch —
thousands of Bazel actions). Bazel also printed, for the first time:

```
ERROR: Error during action cache initialization: Failed to load filename index data.
Corrupted files were renamed ...
```

### Why it happened (root cause)
Two independent factors converged:

1. **Corrupted Bazel action cache.** Bazel keeps an *action cache* recording what has
   already been built. It got corrupted, so Bazel discarded it and re-ran every action
   from scratch. This is what forced the big recompile — it was **not** caused by the
   one-line `absl::InitializeLog()` source edit.

2. **`rsync` touched source timestamps.** `rsync -avz` was updating modification times
   on files inside the tracked source tree. Bazel keys off input timestamps/content, so
   changed mtimes made it treat inputs as "new" and rebuild. (Note: the `mediapipe/`
   workspace itself was excluded from rsync, so its *source* was never overwritten — the
   trigger was the cache corruption plus timestamp churn on tracked inputs.)

### The complicating factor: disk space
The rebuild collided with a tight disk situation on the board:
- Total disk: **25 G**, with only **~4.4 G free** (82% used).
- The Bazel cache alone was **~4.4 G**.

A from-scratch MediaPipe build needs more headroom than that, so the interrupted/failed
builds were as much a **disk-space** problem as a cache problem.

### Recovery / resolution
- Verified free space up front (the step that, when skipped, causes another interrupted
  build).
- Decided **not** to delete downloaded external deps (OpenCV/TensorFlow/Abseil sources) —
  they're fetched inputs, not the stale part, and re-downloading is the expensive part.
- Clean rebuild path settled on: `bazel clean` → `make m2demo` (preferred over a bare
  `bazel build`, because the `m2demo` target also syncs canonical `mediapipe_files/`
  into the Bazel tree and applies the palm-detector patch).
- Adopted a safer sync going forward using `rsync -a --info=progress2` with a
  `--dry-run` preview and the full exclude list above, so build artifacts and the
  mediapipe workspace are never disturbed by a sync.
